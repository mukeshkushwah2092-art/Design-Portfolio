01 · Overview

The problem worth solving

Document collaboration tools are used daily by millions — yet most of them feel designed for the system, not the user. Menus are buried, actions are unclear, and onboarding is practically non-existent. Users waste cognitive energy navigating the tool instead of doing the work that matters.

GDOC was designed with a fundamental belief: a great document editor should disappear into the background. Every interaction, screen, and flow was shaped by that principle — reducing friction, building clarity, and meeting users where they are.

02 · Research Insights

Before sketching a single frame, I conducted user interviews, competitive teardowns, and a survey with target users. The findings shaped every design decision that followed.

03 · Design Process

How I approached the work

The process moved through four deliberate phases, each building on the last — grounded in evidence, shaped by iteration, and validated by real users.

01
Discover — Understanding real frustrations
12 user interviews, 3 competitive audits (Notion, Google Docs, Coda), and an affinity mapping session in FigJam to cluster pain points into actionable themes.
02
Define — Aligning on the right problem
Created two primary personas (a solo professional and a team lead), a detailed user journey map, and a clear problem statement: reduce time-to-action for the 5 most-used document features.
03
Design — From sketch to high fidelity
Started with low-fidelity paper sketches, progressed to mid-fidelity wireframes in Figma, then built a fully interactive hi-fi prototype — including a component library and auto-layout responsive frames.
04
Validate — Testing with real users
Ran 5 moderated usability sessions using the Figma prototype. Identified 3 critical friction points, iterated on them, and confirmed improvements in a follow-up round of testing.

05 · Key Design Decisions

The choices that mattered most

Three design decisions had the most significant impact on usability scores and user satisfaction ratings.

A
Contextual toolbar — show what's relevant
Replaced the static, overwhelming toolbar with a contextual one that surfaces only relevant actions based on what the user has selected. Reduced cognitive load significantly in testing.
B
Permission flow redesign — plain language first
Rewrote sharing dialogs in plain language, replacing technical jargon with clear outcome descriptions. Sharing-related support tasks dropped in post-test interviews.
C
Persistent sidebar navigation — predictable wayfinding
Introduced a collapsible sidebar for document structure. Users could see where they were at all times, dramatically reducing back-and-forth navigation between sections.
06 · Outcomes

What the redesign achieved

After two rounds of usability testing and design iteration, the prototype was validated against the original benchmarks. Results were consistent across participant sessions.

⚡
Faster task completion
Core tasks completed 2.4× faster on average compared to the baseline interface used in testing.
🎯
Reduced error rate
Users made 68% fewer navigation errors when finding features — a direct result of the contextual toolbar and sidebar.
😊
Higher satisfaction scores
Post-test satisfaction rose from 3.1/5 to 4.6/5 — a 48% improvement in perceived ease of use.
🔄
Scalable design system
Delivered a component library of 80+ Figma components with auto-layout, variants, and token documentation — ready for engineering handoff.
07 · Reflection

What I'd do differently

Every project is a learning opportunity. If I were starting GDOC again, I'd push for earlier lo-fi testing — we spent too much time in mid-fidelity before validating core assumptions with users.

I'd also invest more time in edge case documentation. The happy path was well-designed, but edge cases (empty states, error handling, offline modes) were identified late and required additional iteration.

That said, GDOC remains one of my most thorough design explorations — and the prototype is a testament to what happens when research, design, and validation work in tight feedback loops.
